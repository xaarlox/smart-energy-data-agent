# Інтелектуальний агент для аналізу енергетичних даних (EnergyData Assistant)
Цей проєкт реалізує AI-агента з графічним чат-інтерфейсом, призначеного для аналізу, агрегації та обробки структурованих енергетичних даних (CSV) за допомогою природної мови.

## Постановка задачі
Реалізувати агентну систему, яка здатна приймати текстові запити від користувача, перетворювати їх на виконуваний код для аналізу даних енергоспоживання, та повертати зрозумілі аналітичні висновки. Проєкт демонструє використання мовних моделей для decision-making логіки в роботі з даними.

## Аналіз проблеми та підхід до рішення
Традиційний аналіз енергетичних даних (наприклад, показників розумних лічильників) вимагає знання мов програмування (Python, SQL) або складних інструментів (Excel/BI). Використання великих мовних моделей (LLM) дозволяє створити інтерфейс, де користувач спілкується з даними природною мовою.

**Етапи реалізації**:
1. *Завантаження*: Читання підготовленого CSV-файлу з погодинним споживанням електроенергії (субсет даних [PJM Hourly Energy Consumption з Kaggle](https://www.kaggle.com/datasets/robikscube/hourly-energy-consumption)).
2. *Трансляція*: Перетворення текстового запиту користувача в логіку виконання за допомогою промптингу.
3. *Виконання (Agentic Action)*: Агент самостійно пише код на Python (бібліотека Pandas), виконує його в ізольованому середовищі та аналізує отриманий результат.
4. *Презентація*: Формування фінальної відповіді англійською мовою та виведення її в асинхронний графічний інтерфейс.

## Використані бібліотеки
+ **langchain_google_genai / langchain_experimental** - ключовий фреймворк для створення агента (create_pandas_dataframe_agent). Реалізує парадигму ReAct (Reason + Act).
+ **pandas** - для роботи з табличними даними під капотом агента.
+ **tkinter** - вбудована бібліотека для створення легкого десктопного графічного інтерфейсу (UI) без необхідності розгортання вебсервера.
+ **threading** - для забезпечення асинхронності (виконання API-запитів у фоновому потоці, щоб уникнути зависання UI).
+ **python-dotenv** - для безпечного управління змінними середовища та захисту API-ключа (через файл .env).

## Особливості реалізації
1. **Агентна логіка (Policy / Decision-making)**

   Модель (Gemini 2.5 Flash) не просто генерує текст. Вона працює в циклі: аналізує схему DataFrame -> вирішує, яку функцію Pandas застосувати -> генерує код -> отримує помилку/результат -> коригує код за потреби -> формує фінальну відповідь.

2. **Prompt Engineering та Guardrails**

   Для стабілізації результатів на рівні коду зашито жорсткий системний промпт: `\n\nanalyze only the provided dataframe`. Це блокує галюцинації моделі (запобігає вигадуванню даних з інтернету) та жорстко фіксує мову виводу.

3. **Архітектура проєкту**

   Код розділено на логічні модулі: main.py (точка входу), gui.py (візуальна частина) та ai_agent.py (логіка штучного інтелекту). Це відповідає принципам SOLID та спрощує масштабування.

## Метрики якості та обмеження
Оскільки це генеративна агентна система, а не класичний регресійний/класифікаційний алгоритм (де застосовуються RMSE чи F1), якість оцінюється за такими критеріями:

- **Accuracy (Точність):** Висока для агрегації даних (сума, середнє, пошук максимумів), оскільки агент пише точний код на Pandas. Але потребує чіткого формулювання промптів (Prompt Engineering), щоб уникнути неправильного тлумачення умов.
- **Latency (Затримка):** Час очікування відповіді становить у середньому 3–6 секунд (залежить від складності згенерованого Python-коду та швидкості відповіді Google API).

На наведених скріншотах продемонстровано роботу розробленого графічного інтерфейсу та здатність агента коректно інтерпретувати запити природною мовою:

- **Базовий аналіз структури**: Агент успішно визначає типи даних у завантаженому наборі (дати як рядки та споживання як float64).
- **Пошук екстремумів та статистика**: Система здатна знаходити мінімальне значення споживання енергії (23985.0 MW) та точно прив'язувати його до часової мітки (2002-12-23 03:00:00), а також рахувати статистичні метрики (медіану).
- **Розуміння часового контексту**: Під час запиту "Calculate the total energy consumption for the very first day" агент демонструє високий рівень розуміння даних. Замість того, щоб просто взяти перший рядок таблиці (31 грудня), агент проаналізував стовпець Datetime, визначив хронологічно найдавніший день у наборі даних (19 грудня) та просумував усі наявні для нього показники, видавши абсолютно точний математичний результат (386932.0).

**Загальний висновок**:
Система успішно демонструє мінімальну реалізацію автономного Data-агента. Вона ізолює користувача від необхідності писати код, надаючи швидкий доступ до статистичних висновків через інтуїтивний природномовний інтерфейс.
